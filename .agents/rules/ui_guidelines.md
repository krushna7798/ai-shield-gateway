# Frontend UI & Design Guidelines

This rule is mandatory and must be strictly followed for all frontend code generation, UI component creation, styling, and markup in this workspace.

---

## 1. Core Framework & UI Styling
- **Framework Standard**: All HTML and CSS must utilize standard **Bootstrap 5** (CSS & JS).
- **Sharp-Edged Aesthetics**: Use sharp-edged components throughout the interface. Apply `rounded-0` or explicit `border-radius: 0;` on cards, buttons, inputs, modals, alerts, and containers. Avoid rounded or bubbly component styles.
- **Data Tables**: Prioritize clean, functional, dense, and scannable data tables using standard Bootstrap table classes (e.g., `table`, `table-hover`, `table-bordered`, `table-striped`, `align-middle`, wrapped in `table-responsive`).
- **Typography & Clean Layout**: Favor clean, legible typography and high-contrast, professional, and accessible layouts.

---

## 2. Strictly Prohibited Design Patterns
Under no circumstances should the following elements be generated:
- **No Purple Gradients**: Absolutely no purple gradients, violet/indigo neon glows, or cliché AI gradient backgrounds (e.g., linear/radial purple-to-pink or blue-to-purple blends).
- **No Pill-Shaped Buttons**: Do not use `rounded-pill` or full-radius oblong/capsule buttons (`border-radius: 9999px`). Keep all buttons strictly sharp-edged (`rounded-0`).
- **No Emoji Icons**: Do not use emojis (e.g., 🚀, ✨, 🔥, 💡, 🤖, 📈) as interface icons, in button text, or inside headings. Use standard SVG icons or Bootstrap Icons if icons are required.
- **No Em Dashes**: Never use em dashes (`—` or `&mdash;`) in headings, body copy, or UI text. Use standard punctuation such as commas, hyphens, colons, or separate sentences.
- **No Excessive Motion**: No over-the-top scroll animations, parallax shifts, custom cursor effects, magnetic cursor followers, particle backgrounds, or distracting reveal triggers. Keep motion minimal, purposeful, and standard.

---

## 3. Copy, Content & Marketing Authenticity
- **No Vague Hero Texts**: Avoid generic, empty slogans (e.g., "Supercharge your workflow", "Unleash the future of innovation", "The next-gen solution"). All hero headings and descriptions must be concrete, descriptive, and specific to the actual utility of the application.
- **No Fake Social Proof**: Never generate fake user reviews, fictitious testimonials, made-up quotes, or inflated client logos.
- **No Fake Counters**: Do not generate fake metric counters, tickers, or simulated statistics (e.g., "10,000+ satisfied users", "99.9% automated success").
- **No AI-Slop Copy & Photos**: Do not output generic placeholder copy, repetitive boilerplate, or synthetic AI-slop imagery. Use real functional UI elements, clean SVG diagrams, or authentic context-specific graphics.
- **Remove AI Attribution Tags**: Ensure any default "Made with AI", "Generated by AI", "Created with AI", or related badge tags and watermarks are completely excluded or removed.

---

## 4. Routing & Project Structure Requirements
Ensure the application structure and routing adhere to the following architecture:
- **Custom Domain Ready**: Base URLs, asset paths, and routing must support hosting on a custom domain without hardcoded local URLs or broken relative links.
- **Standard Favicon**: Include support and linking for a standard favicon (`favicon.ico` or SVG/PNG) in `<head>`.
- **Legal & Compliance Pages**:
  - Provide a dedicated, routed **Privacy Policy** page (e.g., `/privacy` or `privacy.html`).
  - Provide a dedicated, routed **Terms & Conditions** page (e.g., `/terms` or `terms.html`).
- **Footer Navigation**: Ensure the primary layout or footer consistently integrates clean, permanent navigation links pointing to the Privacy Policy and Terms & Conditions.
